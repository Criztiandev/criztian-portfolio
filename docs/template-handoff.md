## Goal

A reusable Next.js 16 starter that Criztian clones for two kinds of projects: fullstack apps, and static marketing sites. Both now ship a small generic CMS, with the blog as its sample collection. One codebase, no mode flag: static versus fullstack is decided by which routes exist and by the host (Vercel or any Node host).

Success means a fresh clone passes `pnpm check` and `pnpm build`, every mandated library (tRPC, TanStack Query, Jotai, shadcn + motion, zod, Supabase, Resend) has a real consumer, and the house rules (no comments, no `any`, loops over higher-order functions, named types only in `src/type`, service-repository layering) are enforced by ESLint rather than discipline.

## How-to notes

- `pnpm check` runs lint (`--max-warnings=0`), `next typegen && tsc --noEmit` and `node --test "test/**/*.test.ts"`. `pnpm build` must pass with no `.env.local` present.
- `pnpm test:e2e` builds the app and serves it on port 3010, with the Resend mock on 3011 and the PostgREST mock on 3012. All three ports must be free. Without `E2E_USER_*` the app builds against the mock; with them it uses the local stack, which must be running. A new machine needs `pnpm exec playwright install chromium` once. Failed runs keep traces with the E2E password under `test-results/`.
- An empty variable on the command line beats `.env.local`. `E2E_USER_EMAIL= E2E_USER_PASSWORD= pnpm test:e2e` runs the suite against the PostgREST mock, and `NEXT_PUBLIC_SUPABASE_URL= NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY= pnpm build` builds as if there were no Supabase env.
- `pnpm db:reset` deletes users. Recreate the E2E user in Studio, or with `POST http://127.0.0.1:55321/auth/v1/admin/users`, header `apikey` = the secret key from `pnpm exec supabase status`, body `{"email", "password", "email_confirm": true}` with the values from `.env.local`.
- Docker Desktop must be running before `pnpm db:start`; it also starts the portfolio stack, which no longer conflicts. When `pnpm test:e2e` or `pnpm build` dies on `ECONNREFUSED 127.0.0.1:55321`, Docker Desktop is not running: start it and the containers come back with their data.
- A home page test that fails on an old heading after the row is gone: delete `.next/cache/fetch-cache`. A build within the hour reuses the rows the last build read. And know that `pnpm test:e2e` deletes the local `home` and `theme` entries every time it runs.
- After deleting a route file, delete `.next/dev/types` before `pnpm check`. `next typegen` rewrites `.next/types` only, tsconfig includes both folders, and the stale `validator.ts` still imports the deleted page.
- Writing editor tests: after clicking a toolbar button, wait for the editor to be focused before typing, because Tiptap focuses on the next animation frame. Base UI keeps disabled toolbar buttons focusable with `aria-disabled`; Playwright treats that as disabled.
- Writing Playwright tests: files end in `.spec.ts`, and `getByRole("alert")` is always scoped to the form, because Next's route announcer is also a `role="alert"` element on every page. Tests that publish or delete live entries go in `cms.spec.ts`, which runs in order: parallel purges of the page cache made the site journey fail 2 runs in 5. Answer a `window.confirm` inside a `page.once("dialog")` listener registered before the click; an unhandled dialog freezes the click. Ask for the Publish button with `exact: true`: without it the name also matches the Publish date button. The toast "Published" and the chip share their text, so the test finds the toast by `[data-slot=toast-title]`. The calendar is a `dialog`, so find it by name ("Publish date"). A post's Settings is a section button in the editor's hierarchy (`exact: true`), not a dialog. After a click in the frame, check the focus with `toBeFocused()` only: `setFocus` runs in a timeout and Tiptap focuses on the next animation frame, so a one-shot read races. Find a color field with `getByLabel("Text", { exact: true })`: its picker is named "Text color picker", and `fill` works on both. Chromium reports a color that comes from an `oklch` token as `lab(...)`, and one from the palette's hex rule as `rgb(...)`. In the page editor, find the frame with `page.frameLocator('iframe[title="Page preview"]')` and read it with CSS locators (`frame.locator("h1")`); `page.frame({ url: /\/preview\/home\/canvas$/ })` gives the frame for `evaluate`. A click inside the scaled frame lands where it should. The hierarchy rows are links named by the collection label (`exact: true`, because the back link is "Back to Dashboard"), and the sections are buttons with `aria-current="true"`. A field of an unselected section is in the DOM but hidden: `toHaveValue` works on it, a click does not. A click on a section in the frame hides the focused field of another section, so the focus falls to `body`.
- `NEXT_PUBLIC_*` values are inlined at build time. Run manual checks on port 3020 (`pnpm exec next start -p 3020`), because 3010 belongs to Playwright. Find the listener with `netstat -ano | grep :3020` and stop it with `taskkill //PID <pid> //T //F`. Never `taskkill //IM node.exe`: it kills Claude Code too.
- `pnpm db:types` must run through pnpm (PowerShell `>` writes UTF-16). The generated file is ignored by ESLint and Prettier.
- `components/ui/toast.tsx` has a hand-added `motion-reduce:transition-none`; keep it if the item is re-added with `--overwrite`.
- Claude Code quirks: keep Bash commands under 5 KB; a double backslash in a Bash command reaches the shell as one, so write regex literals with the Edit or Write tool; run ad-hoc Node probes with `node --input-type=module -e "$(cat <file>)"` from the repo root so packages resolve.
- A workflow agent that gets its own git worktree starts on `master`, not on the current branch, and never has uncommitted work: tell it to run `git checkout --detach <commit>` first, and paste what it needs into its prompt. The worktrees land in `.claude/worktrees/`, which lint in the main tree picks up, so remove them before `pnpm check`. `git worktree remove --force` fails there on long paths; `cmd /c 'rd /s /q "\\?\<full path>"'` finishes the job, then delete the `worktree-*` branches.
- When continuing: load `supabase-postgres-best-practices` before touching SQL or RLS, read `node_modules/next/dist/docs` before Next code (AGENTS.md rule), and keep this file and the linked doc updated instead of starting a second handoff.
